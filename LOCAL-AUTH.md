# Реальный вход на Lenovo

Единственный рабочий проект: `C:\Users\V13\IdeaProjects\Timeax`. Настройка ниже относится к запуску на этом ноутбуке. Хостинг и DNS она не меняет.

- Обычный `npm.cmd run dev -- --port 5177` оставляет вход и регистрацию закрытыми.
- `npm.cmd run dev -- --port 5177 --real-auth` включает форму по адресу `http://127.0.0.1:5177/register/agency`; повторный вход — `http://127.0.0.1:5177/login`. Сервер слушает только loopback. При неполной конфигурации или недоступной роли он не запускает вход.
- Для этого этапа используется один email из конфигурации, настоящий код Supabase и серверное сохранение заявки. Вход не создаёт аккаунт. Подтверждённая почта и заявка не дают доступа к данным агентства. Кабинет и членство проверяются отдельно.

## Что нужно до первого реального письма

1. В текущем проекте Supabase проверь Email provider, шаблон с кодом нужной длины, SMTP и действующий Before User Created hook. Этот режим сейчас вызывает обычный Supabase OTP, поэтому действующий hook должен разрешать именно согласованный сценарий. Не отключай hook и не открывай signup глобально ради локальной проверки.
2. Проверь разрешения узкой роли `timeax_pending_registration_login` и статус допуска к подключению. По состоянию на 26 ноября роль имеет доступ к двум RPC, но находится в состоянии NOLOGIN. У этой роли уже был задан пароль; заново вводить его в базу не надо, если он сохранён и не менялся. Проверка перед запуском сверяет TLS, права и определения двух RPC. Другие десять паролей эта ветка не читает. Отдельно согласуй, как действующий hook должен допускать создание пользователя.
3. Скопируй шаблон `server/operator/local-auth.env.example` в `.timeax-auth.local` в корне проекта. Проверь параметры Session Pooler, сохрани сертификат CA или укажи его PEM с переносами `\n`. В поле пароля введи значение от узкой роли, не административный пароль и не ключ `service_role`. Файл `.timeax-auth.local` исключён из Git. Не отправляй его в чат и не коммить. Длина кода в шаблоне — 8; проверь соответствие текущему Supabase.
4. После подготовки пройди по порядку: запросить код на свой email, ввести полученный код, сохранить заявку агентства, выйти, вновь войти через новый код и увидеть ту же заявку.

Автотест с подменой почты и хранилища проверяет путь через реальный локальный HTTP-сервер; он не подтверждает доставку письма и запись в живой кластер.
