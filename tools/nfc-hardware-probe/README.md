# Timeax: проверка NFC-оборудования перед пилотом

Это отдельная диагностика. Она не подключается к Timeax, не настраивает карты, не активирует режимы учёта и не записывает рабочие смены. Начинай с одной карты, которая не используется для рабочего учёта. Не выставляй приложению доступ к рабочей базе или учётным записям.

## 1. Lenovo и USB-ридер, если он будет в комплекте

В PowerShell из корня Timeax:

```powershell
java .\tools\nfc-hardware-probe\windows\PcscReaderProbe.java
```

Запусти один раз без карты и один раз с картой над контактной зоной ридера. Проверка использует [стандартный Java-интерфейс PC/SC](https://docs.oracle.com/en/java/javase/26/docs/api/java.smartcardio/javax/smartcardio/TerminalFactory.html): ищет доступные ридеры и проверяет наличие карты. Она не открывает карточную сессию и не посылает картам команды.

| Результат | Что это означает |
|---|---|
| `reader-ready`, код 0 | Ридер отвечает. Если `cardsPresent` вырос с 0 до 1, ридер видит карту. Это не проверка модели чипа. |
| `no-reader`, код 2 | Доступный PC/SC работает, но не сообщает ни одного ридера. |
| `pcsc-unavailable`, код 3 | Не удалось получить статус от PC/SC. Это **не** доказывает отсутствие ридера. Проверь, подключён ли он и видит ли его Диспетчер устройств Windows. |
| `partial-reader-status`, код 4 | Ридеры видны, но не все ответили на вопрос о наличии карты. |

Без USB-ридера пропусти этот этап. Никакой ридер или драйвер не ставится автоматически.

## 2. Терминальный Android, если выберем Android для пилота

Исходники лежат отдельно в `tools/nfc-hardware-probe/android`. Пробник запрашивает только NFC, не запрашивает интернет или профиль Timeax, не открывает считанные ссылки и не сохраняет UID, NDEF, ключи или результаты. Android может прочитать NDEF автоматически в выбранном режиме; это не команда записи, но обычное чтение SDM может увеличить счётчик самой карты.

Открой этот каталог как отдельный проект Android Studio. Для сборки нужны JDK 17, SDK Platform 35, Android SDK Build Tools 35.0.0 и Gradle 8.13; Android Gradle Plugin 8.13.2 уже зафиксирован. Если Android Studio просит дистрибутив Gradle, укажи локально установленный 8.13. [Совместимость инструментов](https://developer.android.com/build/releases/agp-8-13-0-release-notes). На Lenovo с этими инструментами:

```powershell
Set-Location .\tools\nfc-hardware-probe\android
gradle :app:assembleDebug
```

Получится `app\build\outputs\apk\debug\app-debug.apk`; Android Studio может запустить его на физическом Android 9+ с NFC. Для отладки используй только свой компьютер. Не публикуй APK: это локальный диагностический инструмент, не терминал учёта.

1. На Android включи NFC и открой **Timeax: проверка NFC**.
2. Сначала нажми **Проверить технологию карты**, затем приложи тестовую карту. Для NTAG 424 DNA ожидаем NFC-A и ISO-DEP. Такой результат означает совместимость интерфейса; он не подтверждает модель или подлинность чипа.
3. Если на карте уже есть подготовленная NDEF-ссылка, останови первый тест и нажми **Проверить запись HTTPS**. Приложи ту же карту дважды, убирая её между касаниями. Запиши только: запись найдена, значение такое же или отличается. Отсутствие записи на пустой карте ожидаемо. Изменение значения не подтверждает свежесть касания.
4. Нажми **Остановить и очистить**. Не записывай на карту данные для обхода этого теста.

Проверка использует штатные Android [reader mode](https://developer.android.com/reference/android/nfc/NfcAdapter#enableReaderMode(android.app.Activity,android.nfc.NfcAdapter.ReaderCallback,int,android.os.Bundle)) и [cached NDEF](https://developer.android.com/reference/android/nfc/tech/Ndef#getCachedNdefMessage()); защищённых NFC-команд нет.

## 3. iPhone 14 Pro: тест уведомления, не учёт времени

Приложи подготовленную тестовую NDEF-карту с известным HTTPS-адресом к разблокированному iPhone с включённым экраном. Для первого теста хватит подтвердить появление системного уведомления; неизвестные ссылки не открывай. Убери карту и повтори. Отсутствие уведомления на пустой карте ничего не говорит о поддержке чипа. Если уведомление приходит, это проверка открытия ссылки, а не доказательство того, что Safari способен сам провести защищённый обмен с картой. [Apple: чтение NFC в фоне](https://developer.apple.com/documentation/CoreNFC/adding-support-for-background-tag-reading).

## Что записать после теста

- Модель каждого телефона/ридера, версия ОС, тип карты из маркировки или заказа.
- Видно ли ридер в Windows, видна ли карта, показал ли Android NFC-A и ISO-DEP, было ли уведомление на iPhone.
- Повторяется ли результат после отхода карты. Достаточно кратких «да/нет/не проверяли»; не пересылай UID, содержимое ссылки или ключи.

Если оборудование читает чип, следующим этапом остаётся проверить **защищённый обмен на реальной карте** и отдельную привязку карты или терминала к агентству, производству и роли. Не связывай результаты этой проверки с табелями. Подробнее: [границы пилота](../../server/operator/nfc-attendance-pilot.md).

### Локальные проверки разработчика

```powershell
.\tools\nfc-hardware-probe\Test-Probe.ps1
```

Проверяются JSON-отчёт Windows, локальная классификация HTTPS и манифест Android. Это не сборка APK и не замена проверке на телефоне.
