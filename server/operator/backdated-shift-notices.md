# Backdated worker shifts
- Ordinary manual entries (including later the same Warsaw day) retain existing assignment, archived-period, and overlap checks. A saved self-entry whose shift date is before the Warsaw submission date creates a durable notice for its own agency, for internal and connected-factory modes. No email or changes to permissions/historical grants.
- An internal worker with a current assignment and manual entry enabled can submit hours before the recorded assignment start. The request is not a timecard; the agency reviews it under the bell. Approval reuses the canonical write and archive/overlap checks and records the reviewing administrator. Rejection does not create a timecard. Connected factories retain their existing placement/approval rules.
- The notice trigger and request workflow start only after the migration. Historical records do not produce a flood of past notices.
- Release: Back up the current internal timecards RPC definition in the normal operator recovery channel. Run the reviewed migration server/operator/backdated-shift-notices.sql on the database selected for Timeax. Its guard requires the previous verified internal RPC fingerprint. Capture the new exact returned fingerprint and update TIMEAX_AGENCY_TIMECARDS_RPC_SHA256 when deploying the matching application. The current fingerprint gate will temporarily reject the internal timecard lane until the pin matches; coordinate the rollout and verify availability. No change is required to the factory RPC fingerprint. Do not publish this app build as a completed feature before this database step. Verify new pending lists/notice reads and old timecard paths after release.
