# Timeax phone notifications
The bell remains the authoritative inbox. Web Push is an optional, out-of-app hint, not a delivery receipt. This pilot watches new Team deliveries (messages, absences and schedules that have recipients), new worker connections, and backdated notices and review requests if installed before the Push migration. It does not backfill old events. The server queues a compact job for each subscribed device/workspace, delivers a generic localized message (no worker, hours, or message text), and opens the workspace inbox. The service worker has no fetch handler or cache.
## Release
1. Use the canonical HTTPS origin serving the durable login sessions. Deploy the backdated-shift DB migration before this one if shipping both. Review and apply server/operator/web-push.sql; run the role/password provisioning through the normal secure ops channel. Use an independent NOINHERIT credential for timeax_web_push_login; never modify another lane. Pin the exact returned web_push_sha256.
2. Generate a single P-256 application-server key pair with the locked web-push library. Keep the private key in the server environment only. Configure TIMEAX_WEB_PUSH_DB, TIMEAX_WEB_PUSH_RPC_SHA256, TIMEAX_WEB_PUSH_PUBLIC_KEY and TIMEAX_WEB_PUSH_PRIVATE_KEY. Do not commit secrets or print credentials in deployment logs. Retain the same key across deploys. The feature stays off if preflight/config is missing; no new commercial service is required.
3. Verify the manifest and service worker are served with correct MIME on timeax.pl. On iPhone add Timeax to Home Screen as a web app and open its icon; on Android open with a supporting browser. In the bell enable notifications. Test two distinct accounts on real devices: create a message, close Timeax and lock the phone, verify the generic system alert and the authenticated inbox on tap. Test deny/disable, immediate sign-out, normal session expiry, and reconnect. Do not mark delivery verified from simulated tests or provider acceptance.
4. Run the delivery loop on an always-on instance if prompt background delivery is required; a sleeping web service can delay jobs until it wakes. The bounded lease allows recovery after restart and expired jobs/endpoints are cleaned. Job queue and subscription state expire, but the inbox is unaffected if push delivery is unavailable.
